# Hermex Plus — Stability Roadmap (D. stability-roadmap.md)

**Статус:** план последующих действий, код не менялся.
**Приоритеты:** P0 — потеря данных / критичная недоступность / безопасность; P1 — нарушение основного сценария; P2 — повторяющиеся задержки / заметная деградация UX; P3 — диагностика и качество жизни.

---

## P0 — sessions load failed (network.url.-1015)

| Поле | Значение |
|---|---|
| Подтверждающие данные | 1 событие в JSONL: `sessions load failed`, `screen=SessionList`, `category=network.url.-1015`, версия 3.9.67 |
| Влияние на пользователя | Список сессий недоступен, пользователь не может открыть чат |
| Степень уверенности | Событие VERIFIED; причина UNKNOWN (место генерации не найдено в просмотренном коде) |
| Минимальный следующий шаг | Найти в коде место генерации события с категорией `network.url.-1015` и экраном `SessionList`; просмотреть обработку ошибок загрузки сессий |
| Риск | Низкий (единичное событие в выборке) |
| Необходимые тесты | XCTest: сценарий отказа загрузки сессий, восстановление после повторной попытки |
| Критерии приёмки | Ошибка не блокирует UI бесконечно; есть механизм повторной попытки или отображение состояния |

## P1 — Кадры >50 мс и просадка до 60 Гц на 120 Гц дисплеях

| Поле | Значение |
|---|---|
| Подтверждающие данные | `frames.maxMs` до 1403.6 (3.9.67) и 3442.8 (3.9.68); `b_gt_50` 1481 vs 654 кадров; p50 ≈ 16.7 мс |
| Влияние на пользователя | Видимые фризы при скролле и стриминге, отсутствие плавности 120 Гц |
| Степень уверенности | События VERIFIED; причина UNKNOWN (гипотезы G1–G4) |
| Минимальный следующий шаг | Instruments Time Profiler на сценарии «скролл во время стриминга» (критический путь кадра) |
| Риск | Средний (нужен доступ к macOS/Xcode/устройству) |
| Необходимые тесты | Воспроизводимый сценарий скролл+стриминг, замер кадров до и после |
| Критерии приёмки | Выявлена конкретная операция на критическом пути кадра; предложено минимальное изменение |

## P2 — heavyOp пустой в freeze/jank

| Поле | Значение |
|---|---|
| Подтверждающие данные | Код `HeavyOperationTracker` (MainThreadWatchdog.swift:10–78): трекер покрывает только инструментированные пути, работает только на main thread, операция может завершиться до фиксации фриза |
| Влияние на пользователя | Косвенное — затрудняет диагностику, не влияет на UX напрямую |
| Степень уверенности | VERIFIED (код и логи подтверждают пустое поле) |
| Минимальный следующий шаг | Определить, какие пути (SSE, Cache Read, Decode) действительно блокируют main thread во время фризов; добавить инструментацию только для них |
| Риск | Низкий |
| Необходимые тесты | Тест трекера: операция в полёте при симуляции фриза |
| Критерии приёмки | Для воспроизводимого фриза `heavyOp` содержит непустую метку или явно зафиксировано, что операция не установлена |

## P3 — Over-validation метрики кадров (исправление предыдущей ошибки анализа)

| Поле | Значение |
|---|---|
| Проблема | Предыдущий отчёт утверждал `frames p50 = 16669 мс` — значение не существует в логах (путаница единиц) |
| Влияние | Ложные выводы о бюджете кадра и частоте дисплея |
| Минимальный следующий шаг | Задокументировать правильную семантику `frames.durationMs` (p50 интервалов между кадрами за 2-сек окно, мс); исключить 16669 мс из всех документов |
| Риск | Низкий |
| Критерии приёмки | Все документы используют верные единицы и семантику |

## Порядок реализации

1. **Определить место генерации `sessions load failed`** (P0) — чтение кода, поиск по `-1015` и `SessionList`.
2. **Instruments профилирование** (P1) — сценарий скролл+стриминг, критический путь кадра.
3. **Расширение диагностики** (P2) — только для путей, подтверждённых профилированием.
4. **Исправление документации** (P3) — убрать ошибочное значение 16669 мс.

Никаких изменений кода, коммитов, пушей или релизов до отдельного разрешения.
